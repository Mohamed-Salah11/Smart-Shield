Log Forwarding

Optionally mirror SmartShield audit events to an external SIEM as RFC 5424 syslog or CEF.

SmartShield's built-in SIEM — System Logs, the SOC Console and the SOC Portal — is the default and primary SIEM for this appliance. Log forwarding below is optional and disabled by default; enable it only if your organization also operates an external SIEM (Splunk, FortiAnalyzer, QRadar, Elastic, Graylog…) that should receive a copy of these events.

External SIEM Collector (optional)
Events are tailed from the built-in event store and also streamed to the external collector below. The built-in SIEM keeps working regardless of this setting.

Enable log forwarding

When enabled, new events are forwarded starting from now (history is not replayed).

Secret-bearing fields in event details are redacted before forwarding. UDP is fire-and-forget; use TCP or TLS for reliable delivery.

Verify upstream TLS certificate

Recommended. Disables hostname & chain validation when off (use only for self-signed lab collectors). Applies only when transport is TCP + TLS.

Leave blank to use the system trust store. When set, this PEM is used to verify the upstream collector's certificate.

Event Retention
Bound the indexed events table so search and dashboards stay fast.

Automatically prune old events

Background job runs hourly. The audit-log file on disk is rotated separately by newsyslog and is not affected.

Default 90 days to mirror the audit-log file rotation policy. Rows older than this are deleted from the indexed events table.

Syslog Listener (UDP)
Accept syslog from other hosts and ingest it into the built-in SIEM.

Enable UDP syslog listener

Inbound RFC 3164 / RFC 5424 messages are written through log_event with category external_syslog.

Default 5140. Port 514 collides with the FreeBSD system syslogd unless you disable it first.

Trust sender-supplied hostname

When off, SmartShield uses the packet's source IP as the canonical host. Turn on only if your senders are trustworthy.
