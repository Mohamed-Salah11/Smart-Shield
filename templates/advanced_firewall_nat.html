When this option is enabled, fragments will remain in this core, fragments are buffered until they form a complete packet, and only the completed packet is passed on to the filter. • Interface Bound States are more strict and secure. States are bound to specific interfaces by their OS/state name (e.g. igb3). If a packet matches the same source destination and protocol but arrives on any other interface, it will be dropped and not allowed. Floating States will match regardless of the interface on which the packet arrives. This is the most secure but in certain use cases a state table may be reset to handle packets from any network where state table rules may be duplicated or interface with no inbound path may continue.
• Floating States are less secure, more lenient in their checks, and are not strictly associated with any interface. The interface is tracked in state information and not enforced. The policy affects NAT and filter rules, with both of these policies allows a gateway to be assigned per interface. However, this relaxed policy may allow connections to be monitored or take unexpected paths if the routing table can be manipulated.

Network Address Translation
The pure NAT mode uses a set of NAT rules to direct packets to the target of the port forward. It has better scalability, but it must be possible to accurately determine the interface and gateway IP used for communication with the target at the time the rules are loaded. There are no inbound limits to the number of ports other than the limits of the protocols. All protocols available for port forwards are supported.
The NAT + proxy mode uses a helper program to send packets to the target of the port forward. It is useful in setups where the interface and/or gateway IP used for communication with the target cannot be accurately determined at the time the rules are loaded. Reflection rules are not created for ranges larger than 500 ports and will not be used for more than 1000 ports total between all port forwards. This helper only supports TCP and UDP protocols. The Pure and UDP protocols are supported.
Individual rules may be configured to override this system setting on a per-rule basis.
